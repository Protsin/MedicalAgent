# 安全与产品边界

## 必须保留的原则

1. **规则引擎优先**：每条消息都会先经过本地急症规则；模型只用于改写和补充，不可降低安全级别。
2. **急症直通**：识别到急症警示时，用户界面置顶红色警示，回复第一条包含拨打120或急诊建议。
3. **不诊断、不开处方**：系统只做分诊、就医级别建议、症状整理和追问。
4. **失败更安全**：模型不可用、返回空值或缺少急症升级提示时，使用规则回复。
5. **最小化数据**：界面不收集身份证、住址、联系方式、检查影像等数据。
6. **本地默认**：默认监听 `127.0.0.1`，数据保存在本地 SQLite 文件。

## 已覆盖的急症警示示例

- 胸痛、胸闷伴冷汗、呼吸困难、嘴唇发紫
- 意识不清、抽搐、晕厥
- 一侧无力、口角歪斜、说话不清
- 突发剧烈头痛
- 大出血、大量呕血、黑便伴乏力
- 严重过敏、喉咙发紧
- 剧烈腹痛、严重外伤、头部撞击后呕吐
- 孕期出血、药物过量、误服风险
- 自杀、自伤或结束生命念头

规则还包含简单否定处理，例如“没有胸痛”不会仅因出现“胸痛”二字被判为急症。

## 人工审核要求

上线前必须完成：

- 医务人员审核全部急症规则、科室映射与文案。
- 使用本地真实场景样例测试急症漏报率，目标为 0。
- 明确目标人群、语言和地区；不同地区急救与科室资源可能不同。
- 由法务/合规人员确认数据留存、隐私政策、用户协议和免责声明。
- 制定模型故障、规则误报、用户投诉的运维流程。

## 当前限制

- 规则无法理解所有自然语言、方言、隐含描述或复杂病史。
- 生命体征未强制录入，安全级别可能低估病情。
- 2岁以下幼儿、孕产妇、免疫抑制人群和慢性病急性变化需要格外谨慎，必要时直接就医。
- 当前没有账号、公网传输加密、审计后台和删除流程，不能直接作为生产医疗系统。
